# 함께 주문 — 여러 휴대전화에서 실시간 공유 설정

- **방장 전용 접속:** https://jbmath-dot.github.io/math-class-webtools/group-order/admin.html
- **참여자 전용 접속:** https://jbmath-dot.github.io/math-class-webtools/group-order/index.html

방장은 `admin.html`에서 새 주문방을 만들고, 방장이 생성한 **참여용 링크/QR코드**를 공유합니다. 참여자는 `index.html?r=...&cfg=...` 주소를 통해 들어갑니다. 매장 관리 화면은 참여용 페이지에 포함되지 않습니다.

**기존 주문방:** 이전 버전에서 발급받은 참여 링크를 최초 방장이 이용하던 동일한 브라우저에서 열면 새 방장 관리 주소로 자동 이동합니다. Firebase 익명 인증을 통해 주문방을 만든 UID인지 검사하므로, 동일 링크라도 다른 브라우저에서는 방장으로 접속할 수 없습니다. 방장 주소로 주문방을 새로 만들면 마지막 사용한 방장 링크가 브라우저에 저장되며, 이 링크는 참여자에게 공유하지 마세요.

웹앱은 이미 GitHub Pages에 올릴 수 있는 정적 페이지입니다. **서로 다른 휴대전화에서 주문을 실시간 공유하려면 Google Firebase Realtime Database를 연결**해야 합니다. Firebase 설정 없이 주문방 생성/공유는 동작하지 않습니다.

## 1. Firebase 프로젝트 만들기

1. https://console.firebase.google.com/ 에 로그인하여 새 프로젝트를 만듭니다.
2. **빌드 > Authentication > Sign-in method > 익명(Anonymous)** 로그인을 사용 설정합니다. 선생님들은 Firebase 계정을 만들 필요가 없습니다.
3. **빌드 > Realtime Database > 데이터베이스 만들기**를 진행합니다. 초기 규칙은 제한 모드로 만들고 다음 단계 규칙으로 교체합니다. **Cloud Firestore가 아니라 Realtime Database**를 사용합니다.
4. Realtime Database **규칙(Rules)** 탭에 아래 JSON을 붙여 넣고 게시합니다.

```json
{
  "rules": {
    "rooms": {
      "$roomId": {
        ".read": "auth != null",
        ".write": "auth != null && !data.exists() && newData.child('hostUid').val() === auth.uid",
        "menu": {
          ".write": "auth != null && root.child('rooms').child($roomId).child('hostUid').val() === auth.uid"
        },
        "closed": {
          ".write": "auth != null && root.child('rooms').child($roomId).child('hostUid').val() === auth.uid"
        },
        "orders": {
          "$userId": {
            ".write": "auth != null && $userId === auth.uid && root.child('rooms').child($roomId).child('closed').val() === false"
          }
        }
      }
    }
  }
}
```

참고: Firebase Realtime Database 규칙에서 논리 부정(`!`) 연산자를 데이터베이스 값에 직접 쓰면 그 값이 `null`일 때 `! only operates on booleans` 오류가 발생할 수 있습니다. 주문 마감 상태는 반드시 `=== false`로 비교합니다.

이 규칙에서 방장만 메뉴·마감 상태를 수정하고, 참여자는 자기 주문만 수정할 수 있습니다. **같은 주문방 링크를 가진 사람은 모든 주문자 이름과 주문 내역을 볼 수 있습니다.** 실명·연락처 같은 민감정보를 넣지 않는 것을 권장합니다. 방 링크는 모임 참여자에게만 공유하세요.

## 2. 웹 앱 설정 가져오기

1. Firebase 콘솔의 **프로젝트 설정(톱니바퀴) > 일반**에서 웹 앱(</>)을 등록합니다.
2. SDK 설정에서 **Config** 항목의 객체를 복사합니다. `apiKey`, `authDomain`, `projectId`, `appId` 등을 포함합니다.
3. **Realtime Database URL**을 `databaseURL` 항목으로 넣습니다. 예: `https://PROJECT-default-rtdb.asia-southeast1.firebasedatabase.app` (정확한 주소는 해당 Firebase 프로젝트의 Realtime Database 화면에서 복사).
4. 방장 전용 웹앱(`admin.html`)에 Firebase SDK 구성 코드나 JSON 객체를 붙여 넣고 **새 주문방 만들기**를 누릅니다.

입력 예시(값은 실제 프로젝트의 값으로 교체):

```json
{
  "apiKey": "실제값",
  "authDomain": "PROJECT.firebaseapp.com",
  "databaseURL": "https://PROJECT-default-rtdb.REGION.firebasedatabase.app",
  "projectId": "PROJECT",
  "appId": "1:숫자:web:문자열"
}
```

Firebase 웹 구성 정보는 통상 공개 클라이언트 식별자이며 비밀 서버 관리자 키가 아닙니다. 그렇더라도 **위 데이터베이스 규칙을 적용해야 접근이 제한됩니다.** 웹앱이 만든 공유 링크에는 프로젝트 설정과 추측하기 어려운 주문방 코드가 포함됩니다.

## 3. 방장/참여자 화면 분리

- **방장:** `admin.html` 전용 페이지에서 새 주문방 생성, 매장 탭 추가·이름 변경·삭제, 메뉴 사진 업로드/OCR/사진 자르기, 메뉴·가격 수정, 주문 마감/재개, 참여용 QR코드 및 링크 발급, 매장별 집계를 이용합니다.
- **참여자:** 공유받은 `index.html?r=...&cfg=...`에서 닉네임, 매장 탭, 사진형/목록형 메뉴 선택, 수량·옵션, 주문 확정·다시 선택하기, 매장별 전체 주문 현황만 봅니다.
- **방장 검증:** `admin.html`에서 주문방을 열 때 Firebase 사용자 UID가 해당 방의 `hostUid`와 다르면 `index.html` 참여자 화면으로 이동합니다. 참여자가 주소를 직접 `admin.html`로 바꿔도 다른 주문방의 메뉴를 수정할 수 없습니다. 권한은 Firebase 규칙에서도 제한됩니다.
- **방장 기기 유지:** 브라우저 저장정보를 삭제하거나 다른 휴대전화로 이동하면 익명 인증 UID가 달라져 기존 방장 권한을 복구하지 못할 수 있습니다. 최초 방장을 유지하려면 동일한 브라우저·기기를 사용하세요.

## 4. 현장에서 사용하기

- **방장:** 새 주문방 생성 → 메뉴판 전체 사진 촬영/선택 → "사진에서 메뉴·가격 인식하기" → 메뉴별 이름·가격·사진 추천 확인 → 필요한 경우 "메뉴판에서 사진 자르기"로 원하는 음식 사진 부분을 드래그 → "확인한 메뉴 등록하기". 자동 제안 사진이 엉뚱하면 "사진 제거"를 누르세요. 메뉴마다 사진을 직접 선택하거나 메뉴만 수동 입력해 등록할 수도 있습니다.
- **메뉴 수정:** 방장의 메뉴 관리 화면에서 각 메뉴 옆 "수정"/"삭제"를 누릅니다. 메뉴명·가격 수정은 연결된 모든 화면과 합계에 바로 반영됩니다. 삭제된 메뉴의 기존 주문에는 주문 당시의 메뉴·가격을 보존합니다.
- **공유:** 링크 공유 또는 QR코드로 선생님 10명에게 전달합니다.
- **참여자:** 각자 휴대전화에서 링크 접속 → 이름 또는 닉네임 입력 → 사진 있는 메뉴는 음식 사진·메뉴명·가격이 보이는 카드를 누르고, 사진 없는 메뉴는 목록형 버튼을 눌러 선택 → 수량·옵션 입력 → 주문 확정. 변경할 때는 "다시 선택하기"로 기존 선택을 교체합니다.
- **함께 보기:** 주문자별 내역, 메뉴별 수량·금액, 전체 합계가 각 휴대전화에서 실시간으로 동기화됩니다.
- **방장:** 주문 접수 마감/재개를 제어합니다.
- **가격 옵션:** 메뉴에 없는 샷 추가 등의 옵션 가격은 자동 산정하지 않으므로 필요한 경우 별도 가격의 메뉴로 등록하세요.
- **사진 인식:** 브라우저에서 Tesseract.js 한글·영문 인식 모델을 다운로드합니다. 네트워크가 느리면 시간이 걸리고 인식 오류가 있을 수 있어 반드시 메뉴·가격을 확인하세요. **원본 메뉴판 전체 사진은 서버에 업로드하지 않습니다.** 다만 개별 음식 사진을 잘라 등록하면 작은 JPEG 이미지가 Firebase Realtime Database의 해당 메뉴 데이터에 저장되어 모든 참여자에게 공유됩니다. 한 장의 메뉴판에서 음식 사진을 분리하는 작업은 이미지 배치에 따른 휴리스틱 자동 추천이므로 결과를 반드시 확인하고 필요하면 직접 영역을 지정하세요.

## 여러 매장 탭 사용하기

- **방장:** 주문방을 연 뒤 상단의 **매장별 주문** 탭을 확인합니다. 최초 탭은 **기본 매장**이며, 방장 메뉴 관리의 **매장 탭 설정**에서 해당 이름을 원하는 매장 이름(예: 카페 봄)으로 변경할 수 있습니다.
- **새 매장:** **새로 추가할 매장 이름**을 입력하고 **매장 탭 추가**를 누르면 상단에 새 탭이 생깁니다. 각 탭의 메뉴는 개별 관리됩니다.
- **메뉴 관리:** 원하는 매장 탭을 선택한 뒤 메뉴판 사진을 인식하거나 메뉴·가격·음식 사진을 직접 등록합니다. 등록되는 메뉴는 현재 선택한 매장에만 속합니다.
- **참여자:** 상단에서 매장을 누르면 해당 매장의 사진형/목록형 메뉴와 주문 현황만 나타납니다. 매장마다 메뉴 하나를 선택해 확정할 수 있고, **이 매장 다시 선택하기**로 해당 매장의 주문만 교체할 수 있습니다. 다른 매장 주문은 유지됩니다.
- **집계:** 매장 탭별 주문자, 메뉴 수량, 합계가 따로 표시되며 현황 영역에는 전체 매장 합계도 함께 나타납니다.
- **삭제:** 최초의 기본 매장 탭은 이름만 변경할 수 있습니다. 추가한 매장 탭은 메뉴와 주문이 모두 없을 때만 삭제할 수 있습니다.
- **기존 주문방:** 기능 업데이트 전에 생성된 메뉴 및 주문은 모두 기본 매장 탭으로 표시됩니다. 기존 Firebase 데이터베이스 규칙을 다시 수정할 필요는 없습니다.
- **데이터 구조:** Firebase의 `rooms/{roomId}/menu` 목록에 매장명 레코드(`kind:"store"`)와 매장별 메뉴 레코드(`storeId`)를 함께 저장합니다. 사용자 주문 항목에도 `storeId`를 보존합니다.

## 제한사항 및 보안

- 이 앱은 실제 음식점으로 주문을 전송하거나 결제하지 않는 모임용 주문 취합 도구입니다.
- 실시간 공유에는 인터넷 접속, Firebase 설정, 설정된 규칙, 익명 인증이 모두 필요합니다.
- 모임 참가 인원이 많거나 악의적인 트래픽이 있을 경우 Firebase 사용량 제한·요금이 발생할 수 있습니다. Firebase 사용량 알림과 무료 할당량을 점검하세요.
- 모든 참여자가 서로의 주문을 볼 수 있도록 설계되었습니다. 방 링크가 외부로 유출되지 않도록 유의하세요.
- Firebase 익명 로그인에 쓰인 브라우저 저장정보를 삭제하거나 다른 브라우저로 접속하면 이전 주문의 수정 권한은 이전 익명 사용자에게 남습니다.
- 주문이 끝난 후 Firebase 콘솔의 Realtime Database에서 해당 `rooms/방코드` 노드를 삭제하면 데이터를 정리할 수 있습니다. 개인 정보를 불필요하게 오래 보관하지 마세요.

## 메뉴판 설명 자동 제외 및 음식 사진 매칭

- 방장이 **방장 전용 페이지**에서 전체 메뉴판 사진을 선택하고 **사진에서 메뉴명·가격·음식 사진 추출**을 누르면, OCR 결과에서 가격과 연결된 **메뉴 이름·금액** 위주로 후보를 만들고 긴 설명 문구·홍보 문장·카테고리 제목은 제외합니다.
- 가격이 메뉴명 오른쪽이나 바로 아래에 따로 인쇄된 경우 OCR의 좌표 정보를 이용해 가까운 메뉴명과 짝지으려고 시도합니다. 원본이 흐리거나 여러 열이 뒤섞였을 때는 잘못 연결될 수 있습니다.
- 메뉴판에 음식 사진이 있다면 메뉴명 주변 사진 후보를 탐색해 자동 잘라내기를 제안합니다. **사진 속 음식의 종류를 정확히 식별하는 AI 모델을 탑재한 기능은 아닙니다.** 텍스트 위치, 화면 색상, 질감, 사진 간 중복 여부를 이용하는 휴리스틱이며, 잘못 연결된 사진은 방장이 반드시 확인·수정해야 합니다.
- 음식 사진 후보를 찾지 못했거나 신뢰도가 낮을 때는 사진을 붙이지 않습니다. 해당 메뉴는 참여자 화면에서 **목록형 버튼**으로 자동 표시됩니다.
- **인식된 메뉴 확인 · 수정**의 이름·가격·추천 사진을 확인하고, 사진이 틀리면 **메뉴판에서 사진 자르기**로 직접 사진 영역을 지정하거나 **사진 제거**를 선택하세요. 확인 후에만 **확인한 메뉴 등록하기**로 저장됩니다.

## 설명·뱃지 제외 및 추가 옵션 처리 (2026-10-15)

- 방장의 메뉴판 사진 인식에서 가격과 연결되지 않은 설명·홍보 문구를 최대한 제외하고, `계절메뉴`, `주말한정`, `추천메뉴` 같은 뱃지 텍스트는 메뉴명에서 제거합니다. 사진마다 글자 크기·위치가 달라 최종 등록 전에 방장이 확인해야 합니다.
- `아이스변경`, `샷추가`, `시럽추가`, `휘핑추가` 등 이름이 옵션형이고 가격이 3,000원 이하인 경우 **추가 옵션 후보**로 자동 분류합니다. 방장은 OCR 확인 목록의 **분류** 선택창에서 일반 메뉴/추가 옵션을 변경할 수 있습니다.
- 방장 관리의 **메뉴 추가하기 · 사진 선택**에는 **등록 유형**이 있으며, 추가 옵션을 직접 입력할 수 있습니다. **등록된 추가 옵션**에서 수정·삭제할 수 있습니다.
- 일반 참여자는 매장 탭을 선택하고 일반 메뉴를 누른 뒤 추가 옵션 버튼(예: `샷추가 +500원`)을 선택하거나 해제할 수 있습니다. 예상 결제금액과 개인·메뉴별·매장별 합계는 **(메뉴 가격 + 선택 옵션 가격) × 수량**으로 계산합니다.
- 예: 아메리카노 5,000원 + 아이스변경 500원 + 샷추가 500원 = 1잔 6,000원, 2잔 12,000원입니다.
- 옵션 사진은 자동 연결 대상에서 제외되며, 사진이 없는 일반 메뉴는 목록형으로 표시됩니다. 확실하지 않은 자동 사진 추천은 방장이 직접 수정·제외해야 합니다.
- 기존 주문 데이터도 가격 계산에 계속 사용할 수 있도록 호환성을 유지했습니다. 기존에 일반 메뉴로 저장해 둔 옵션은 방장 화면에서 해당 항목의 **등록 유형**을 **추가 옵션**으로 변경해야 합니다.
- 현재 적용 범위: 사진·텍스트 추출은 브라우저 내 Tesseract OCR과 규칙 기반 매칭입니다. 모든 사진·설명을 정확하게 인식하는 범용 AI 의미 분석은 아닙니다.

## 개별 음식 사진 사용 안내

- 방장이 사진이 들어간 메뉴판 한 장을 등록해도 메뉴명·가격을 인식하고, 텍스트 위치와 이미지 특징에 따라 인접한 음식 사진 후보를 자동 추천합니다. **이미지 인식이 항상 정확한 것은 아닙니다.** 후보 이미지의 내용이 다른 음식이거나 글자를 잘랐다면 "메뉴판에서 사진 자르기"로 올바른 영역을 직접 지정하세요.
- 음식 사진이 없는 메뉴, 자동 추천 사진이 없는 메뉴는 참여자에게 **목록형 메뉴**로 표시합니다.
- 별도로 촬영하거나 갤러리에서 선택한 음식·음료 사진을 개별 메뉴의 추가·수정 화면에 등록할 수 있습니다.
- 방장만 메뉴와 사진을 수정할 수 있으며 일반 참여자는 사진·메뉴명·금액을 보고 주문만 할 수 있습니다.
- 이미지 데이터는 작게 압축되어 Firebase에 저장됩니다. 메뉴·이미지를 매우 많이 등록하면 데이터 사용량이 커질 수 있으므로 필요한 개수만 등록하세요.
